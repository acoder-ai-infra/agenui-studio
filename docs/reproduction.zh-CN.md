# 复刻一张高质量卡片

本文提供可公开、可复制的起点：不需要私有模板、业务数据或代码改造，也不分发任何线上产品规则。

## 1. 使用内置本地数据启动

执行 `make dev`，在“设置”中配置模型，再打开 Studio 首页。初始化器会注册通用的优惠列表 API、
两个格式化算子和 Markdown 设计规则。尚未接入真实数据源也可以先生成：预览数据用于看清设计，
Binder 会在交付前报告仍需补齐的映射。

## 2. 复制这段生成提示词

```text
生成一张面向消费者应用的精致移动端优惠列表卡。

使用白色圆角卡片、16px 内边距和舒适的纵向节奏。顶部有紧凑分区标题，下面展示两条重复优惠项。
每条支持可选缩略图、两行标题、简洁元信息、强调的当前价格、弱化且带删除线的原价、一到两个
状态标签，以及对齐在行内的紧凑主操作。两条重复项之间恰好有一条低对比分隔线；底部是居中、
弱化的“查看更多”动作。请保证移动端可读且不裁切。

若本地优惠数据可用，则绑定真实标题、图片、元信息、当前价格、原价和动作参数，并使用可用算子
格式化金额。若暂时没有合适数据源，仍创建完整可信的预览数据，并报告绑定缺口，而不是删减设计。
```

模型不必逐像素复刻参考图；关键是保留信息层级、视觉节奏和可执行的数据/动作契约。

## 3. 复制这段编辑提示词

```text
保持既有内容和数据绑定不变，只调整视觉：让当前价格更突出，原价保持弱化和删除线；主操作使用
柔和强调色背景；只在重复列表项之间增加一条细分隔线；底部动作保持居中且弱化。不要移动、删除
或修改任何数据绑定与动作。
```

编辑前 Workspace 会解析真实 DSL。它会冻结保护集合并校验基准 revision，因此视觉编辑不会悄悄改写
无关的绑定或动作。若确实需要新增组件，模型会基于工具返回的父子树和兄弟锚点显式声明插入位置。

## 4. 当视觉系统稳定时再加小型规则

通过“设计规则”上传如下 Markdown。规则用于约束设计，不是隐藏模板，也不替代提示词。

```md
# 紧凑移动列表

## 布局

- 使用单一圆角表面，内边距 16px。
- 重复行采用内容与操作并排的结构。
- 仅在相邻行之间放置低对比分隔线，首行前和末行后都不放。
- 底部动作居中，视觉优先级低于行内操作。

## 元素

- 行可以包含图片、标题、元信息、价格组、标签和动作。
- 原价可选，且必须弱于当前价格。
- 标题最多两行；操作在移动端宽度下仍需清晰可读。

## 全局约束

- 保持最小可读触控区域，避免文本裁切。
- 不得虚构内容契约中不存在的字段或动作。
```

公开规则中不要包含内部产品名、URL、设计 Token、阈值或私有业务词汇。Rule Worker 会原子发布解析后的
Markdown revision，下一次生成读取活动 revision。
