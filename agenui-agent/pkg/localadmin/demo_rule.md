# 公开设计规则：基础卡片与列表

这是 AGenUI Studio 自带的公开 Markdown 源文档。项目随附它的已发布标准投影，因此
首次启动无需模型解析即可使用；后续上传或修改 Markdown 时，才由异步 rule worker
解析、校验和发布。

## 全局约束

- 只使用当前 renderer catalog 已声明的组件和属性；不要虚构组件、数据字段、动作或绑定。
- 一张卡只承担一个主要任务。需要主要操作时，只保留一个明确的主按钮。
- 使用 8px 间距节奏：卡片内边距 16px，相邻区块垂直间距 12px。
- 数据缺失时显示明确的加载、空态或不可用状态，不能编造业务信息。

## 布局：摘要卡片

- 卡片根节点使用纵向 `Column`，`padding` 为 `16px`，`gap` 为 `12px`。
- 使用单行主标题展示主要信息，摘要文本可选。
- 若存在操作，将一个全宽 `Button` 放在卡片末尾；按钮文案应为动词短语。

## 布局：信息确认卡

- 顶部可放一行较弱的地点、状态或业务上下文信息。
- 信息区按短标签和值的行进行组织，不增加没有绑定的数据字段。
- 卡片只保留一个明确的确认或查看操作。

## 布局：重复条目列表

- 标题下使用一个重复条目模板；每个条目保持相同组件形状。
- 条目内部使用 8px 间距，分隔线只出现在相邻条目之间。
- “查看全部”只在列表后出现一次，除非输入明确提供条目操作。

## 元素：标题与主要按钮

- 主标题使用 `Text`，视觉权重最高，保持单行且在数据刷新时结构稳定。
- 辅助文本使用较弱颜色与较小字号，不与主标题竞争。
- 主要按钮文字应清楚表达操作，例如“提交”或“查看更多”，不能重复标题。
- 按钮不可用时，仅在输入数据明确声明不可用时禁用；否则不渲染该操作。

## 状态

- 加载时保留卡片层级，并使用简短的加载文案。
- 空态或不可用时保留已知标题，并说明缺失原因；不要用占位业务数据填充。
